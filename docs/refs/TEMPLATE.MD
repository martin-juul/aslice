# SOURCE TITLE

## Source identity

- Original source: REQUIRED canonical URL
- Author/publisher: REQUIRED
- Source version/date: REQUIRED exact revision or explicitly unknown
- Retrieved: REQUIRED UTC date
- Capture type: complete original / licensed excerpt / technical account
- Rights: REQUIRED license and attribution; link retained license text
- Used by: local document sections and the exact claims supported

## Captured material

Capture every relevant prerequisite, algorithm, format, parameter, command behavior, exception, failure, and recovery condition. Preserve tables and examples needed to use the material offline. Distinguish source facts from project decisions. A URL or abstract alone is not a capture.

## Applicability and limits

Name the applicable OS, hardware, tool version, and known omissions. A forum report is evidence of a report, not a verified procedure. Identify any missing source that blocks an implementation claim.

## Project interpretation

Explain how the captured material supports a specific decision and what testing remains. Link related local records; preserve dependency standards too.

## Preservation

Record the exact downloaded bytes, SHA-256, retrieval URL, and transformation where redistribution allows an original. Keep unmodified originals and notices alongside this record. Otherwise write a complete account of the relevant technical facts in original wording, clearly labeled; do not claim it is a verbatim archive. Include the record and assets in SHA256SUMS. Never overwrite an older relied-upon revision silently.
